Section 1 -- ownership evidence that decided the design
--------------------------------------------------------

Gathered while the driver's own debugfs creation was temporarily disabled and
the module was freshly loaded. It shows that DRM core, not the driver, creates
crtc-0/crc and its two files, and routes them to the driver callbacks.

  /sys/kernel/debug/dri/0/crtc-0/
    7861761 drwxr-xr-x 2 root root crc
    crc/control   (reads: "scanout")
    crc/data
    (no crc/source)

  dmesg:
    debugfs: 'control' already exists in 'crc'
    debugfs: 'data' already exists in 'crc'

The EEXIST pair names control and data and never source: core creates exactly
those two and does not create a source file when the source list comes from
get_crc_sources(). The T28 driver-owned copies therefore shadowed core state
that was never set through core's own control write, which is what made a fresh
open of crc/data fail with EINVAL (see section 4).

Section 3 -- two defects found while validating the stock path
--------------------------------------------------------------

3a. Positive return from drm_vblank_work_schedule()

  /usr/src/kernels/7.3.4-100.fc43.x86_64/include/drm/drm_vblank_work.h:65-66
  declares the function int; the binary of drm_vblank_work_schedule() shows it
  returning 1 on its normal queued paths and only negative values for errors.
  sm750_crc_arm() treated any non-zero as a failure, so
  sm750_crtc_set_crc_source() returned 1, crtc_crc_open() propagated it and
  userspace saw:

    openat(AT_FDCWD, "/sys/kernel/debug/dri/0/crtc-0/crc/data", O_RDONLY) = -1 EINVAL

  Fix: arm tests ret < 0, and the work item's re-arm does the same. After the
  fix the same open returns a descriptor and entries arrive (section 5).

3b. The frame has to survive the drawer's exit

  tests/check-scanout-crc.sh draws through a short-lived client and then
  samples. DRM runs lastclose -- which restores the fbdev console mode, and the
  console client owns the frame that gets restored -- when the last file on the
  device closes, so the drawn pattern was replaced by the console's own black
  frame before the first sample. The check now starts the drawer with a hold
  and samples while it still holds the device and master; the sampling logic
  (black frame, write scanout to crc/control, read crc/data) is unchanged.
