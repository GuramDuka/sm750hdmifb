The crc/data uapi contract (correction, review finding)
------------------------------------------------------
Userspace reads the number of CRC values per entry as the first line after
open, "1\n" (src/sm750_drm.c:292, emitted once per open at
src/sm750_drm.c:3337), and then one entry per read as "%u %08x\n"
(src/sm750_drm.c:3362): a decimal vblank count, a space, the CRC as eight hex
digits, newline, with no 0x prefix on either field. libdrm's drmModeCrtcGetCRC
and IGT take the first line as the count and parse entries as "%u %x", so the
earlier "0x%08x 0x%08x" form would be read as a count of 0 and the capture
dropped. tests/check-crc-uapi.sh now asserts the count line, the entry format
and the absence of 0x in the data path, and rejects six planted defects.
