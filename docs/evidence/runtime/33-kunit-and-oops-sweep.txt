## LIVE SWEEP COMPLETED, KUNIT ITSELF DISABLED (SUPERSEDED - see the census at the end)

The sweep is no longer unproven at the gate level: all 21 allowlisted suites
were loaded and unloaded for real on this host, and the gate discovered,
parsed, unmapped and reported their output. What is unproven is KUnit's own
execution, and the reason is environmental, not a bug in the gate:

  - /boot/config-7.3.4-100.fc43.x86_64 has
    "# CONFIG_KUNIT_DEFAULT_ENABLED is not set", so kunit loads with
    enable=0 even though CONFIG_KUNIT_AUTORUN_ENABLED=y.
  - Consequently each suite prints "KTAP version 1 / 1..1 /
    kunit: disabled" and no subtest, and the gate skips with exit 77 naming
    that reason instead of reporting a pass.

Verified on this host:
  - module discovery and the floor (23 .ko.xz files, floor 8);
  - plain modprobe resolution through modules.dep;
  - the live allowlisted loader path (MODPROBE_CMD='sudo -n /usr/bin/modprobe')
    for all 21 suites, with reverse unloads on every exit path;
  - the TAP parser against synthetic logs (four planted defects rejected:
    failing_subtest, missing_suite, missing_totals, totals_mismatch; two
    negative controls accepted: clean_run, skipped_subtest);
  - the oops detector end to end against the live allowlisted
    'sudo -n dmesg' reader, wrapping tests/check-drm-policy.sh and
    tests/check-sm750-pkg.sh, both clean.

## Exit status of a green run (fixed 2026-11-22T23:40Z)

The 8.7 s run recorded above printed 21 "ok" lines and nothing on stderr but
returned rc=1, and never printed the closing "KUnit DRM sweep passed" line.
Cause, isolated: `unload_all()` (installed as the EXIT trap) ended in
`grep -q '^kunit ' /proc/modules && echo "kunit-drm: NOTE ..." >&2`; when the
unload succeeded grep returned 1, the compound list returned 1, and under
`set -euo pipefail` that became the trap's status and the script's rc, which
overrode the intended 0 and skipped the epilogue. The trigger is kunit not
being resident at gate start, which is the state on this host, so the green
run was always reported as a failure.

Minimal reproduction, no modules involved:

$ bash -c 'set -euo pipefail; f(){ grep -q "^kunit " /proc/modules && echo NOTE; }; f; echo REACHED'; echo "rc=$?"
rc=1

Fix: `unload_all()` restructured to plain nested `if grep -q ...; then ... fi`
with an explicit `return 0`, so no compound list can leak a status; the unload
attempts, their best-effort error suppression and the resident-kunit NOTE are
unchanged. The same audit found no other trace-visible function ending in a
compound list.

Pinned by the new self-test control `exit_status_green`, which asserts
`unload_all()` ends in `return 0` and runs a same-shaped trap harness under
`set -euo pipefail` to prove the closing line is still reached:

$ ./tests/check-kunit-drm.sh --self-test
...
control exit_status_green: accepted (green run reaches the closing line, rc 0)
KUnit sweep self-test passed (6 planted defects rejected, 4 negative controls accepted, exit_status_green pinned)
rc=0
