======== 2. the mechanism, read from dkms 3.4.4 ========

`dkms --version` prints `dkms-3.4.4`. `grep -n` over /usr/sbin/dkms:

    1768:do_install()
    1778:    local -r active_link="$dkms_tree/$module/kernel-$kernelver-$arch"
    1783:        old_active_version=$(readlink "$active_link")
    1784:        old_active_version=${old_active_version%%/*}
    1868:            die 6 "Failed to uninstall $module/$old_active_version for kernel $kernelver ($arch)."

The two halves of the mechanism, verbatim (sed -n on the same file):

    local -r active_link="$dkms_tree/$module/kernel-$kernelver-$arch"
    ...
    if [[ -L $active_link ]]; then
        old_active_version=$(readlink "$active_link")
        old_active_version=${old_active_version%%/*}
    fi
    ...
    if [[ $old_active_version ]]; then
        (module_version="$old_active_version" delayed_depmod=1 do_uninstall "$kernelver" "$arch") || \
            die 6 "Failed to uninstall $module/$old_active_version for kernel $kernelver ($arch)."
    fi

So the old version is taken from the link target alone, with no check that the
version is still registered or still on disk, and `do_uninstall` for it needs
`$dkms_tree/$module/$module_version/source/dkms.conf`. The 0.6.1 tree was
gone, so the uninstall died 6 for every kernel and the install never reached
the new module. Recreating the link is dkms's own job on the next successful
install, which is why removing a link with no target is safe.

======== 4. what changed (0.6.2-3) ========

`packaging/sm750hdmifb.spec` release 3 adds a second purge loop after the
version-driven one and before the build loop (:245-251):

    for dkms_link in "$dkms_root/%{dkms_name}"/kernel-*; do
        [ -L "$dkms_link" ] || continue
        if [ ! -d "$dkms_link/" ]; then
            echo "removing dangling DKMS kernel link: $dkms_link" >&2
            rm -f -- "$dkms_link"
        fi
    done

It touches a path only when it is a symlink directly under
`$dkms_root/%{dkms_name}` and does not resolve; dkms always points these links
at a version directory, so `[ ! -d "$dkms_link/" ]` is the resolution test.
