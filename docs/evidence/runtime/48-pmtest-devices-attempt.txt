# 48 - the first armed pm_test cycle: the helper works, the suspend is refused by nvidia

Date:    2026-11-27 11:55Z (host clock 11:55, UTC 08:55)
Kernel:  7.3.4-100.fc43.x86_64
Driver:  0.6.8 loaded (srcversion 3AC8D0650636E51E7169158), rebooted 11:13:29
Command: sudo -n /usr/local/sbin/sm750-pmtest run devices

## 1. Why this run happened

The owner ordered the deferred PM cycle (m09985 item 3). The first attempt at
08:22Z was refused by the helper itself, before any suspend, because
read_pm_test() matched the bracketed level only at the start of the line and so
read `none` for every other level (see commit 37feab9 and the logbook entry of
2026-11-27T11:55Z). After the helper was reinstalled from commit 37feab9
(sha256 9ea7961994aa60977d3cafbec5918ff25c45eca3744d0a44d51808f4ebb1196f) the
same command armed correctly.

## 4. What this proves and what it does not

Proved:
- pm_test armed at `devices` and read back `devices`: the parser defect of
  commit 37feab9 is fixed on the live host.
- the trap restored `none` on exit (`sm750-pmtest: pm_test readback after
  cleanup: none`), so no level is left armed.
- the verdict rule rejected the run for the right reasons: no completion lines
  and changed error counters.
- the driver survived untouched: 0.6.8 still loaded, vtcon1 bound, HDMI-A-1
  connected at 1024x768 75 Hz, PANEL_CURRENT_LINE advancing (0x1c2 -> 0x146),
  vblank counter 3923 -> 4331.

Not proved, and the reason the cycle cannot complete on this host:
- the SM750 suspend and resume callbacks were NEVER invoked. The journal holds
  zero `sm750 ... pm: ` lines in the window, so the driver's PM logging at
  src/sm750_drm.c:5476-5520 did not run at all.
- the suspend aborted on two Tesla P100s (0000:83:00.0 and 0000:84:00.0) whose
  nvidia driver returns -5 from nv_pmops_suspend because
  PreserveVideoMemoryAllocations is set without the procfs suspend interface.
  devices-level testing suspends every device in parallel and aborts on the
  first failure, so one failing unrelated GPU blocks the whole cycle.

## 5. Consequence

P1 stays open and is now blocked by the host, not by the driver: any
`pm_test=devices` cycle on this machine stops at nvidia before the SM750 is
reached, and no allowable user-space action changes that (the two P100s must
either stop failing system suspend or be unbound from nvidia for the duration,
and the display GPU 0000:02:00.0 belongs to the owner's running session).
