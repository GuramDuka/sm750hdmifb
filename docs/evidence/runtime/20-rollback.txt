WHAT THE ERASE PROVED, AND THE ONE HAZARD IT LEFT
======================================================================
  PROVEN (all four are what a rollback has to guarantee):
    1. rpm -q sm750hdmifb -> 'package sm750hdmifb is not installed';
       rpm -qa | grep -c sm750hdmifb -> 0. Clean package database.
    2. dkms status drops to the two orphaned 0.5.9 'built' rows; the 0.6.0
       registrations are gone from /var/lib/dkms and /usr/src/sm750hdmifb-0.6.0
       is removed. Only /usr/src/sm750hdmifb-0.5.9 survives (residue of the
       pre-fix install, see the note below).
    3. The installed object for the running kernel is deleted:
       /lib/modules/7.3.4-100.fc43.x86_64/extra/sm750hdmidrm.ko.xz -> No such file.
    4. THE DISPLAY SURVIVED: card0-HDMI-A-1 connected/enabled/On, CRTC 38 still
       at (0,0) 1920x1080, /dev/dri/card0 still present, kwin_wayland still 2
       processes on card1. Erasing the package does not blank either output.

  HAZARD - the erase leaves an unloadable system, and this is the reason the
  machine was NOT left in the erased state:
    The module remains LOADED (sm750hdmidrm 167936 0 - Live) while its file is
    gone: modinfo now reports 'ERROR: Module sm750hdmidrm not found', and
    'find /lib/modules/$(uname -r) -name sm750hdmidrm*' returns nothing.
    So the console keeps working only because the resident copy is still in
    memory. A reboot - or any accidental 'modprobe -r' - would leave card0
    with no driver and no module to load, i.e. no console on the SM750 output.
    dnf cannot unload a module and this package deliberately has no %postun
    that would, so this is inherent to the design, not a scriptlet bug.

  RESIDUE (pre-existing, not created by this erase): /usr/src/sm750hdmifb-0.5.9
  and two dkms 'built' rows for 0.5.9 remain. They are orphaned by the 0.6.0
  install (0.6.0 owns the /lib/modules path) and are harmless, but they mean a
  future 'dkms install -m sm750hdmifb -v 0.5.9' could still resurrect the stale
  build. Recorded for cleanup; not deleted here because 0.5.9 is outside T11's
  package version and removing it would edit another task's artefact.

======================================================================
DECISION: REINSTALL TO LEAVE THE MACHINE IN THE BETTER STATE
======================================================================
  The erase was executed as proof, then 0.6.0 was reinstalled immediately, so
  the host ends with a module file on disk for the running kernel and 0.6.0 in
  memory. Reason: leaving the machine with a live-but-unloadable driver is a
  worse end state than the one T11 started from, and the acceptance criterion
  asks for a rollback PROOF, not for a permanent downgrade. See
  21-final-state.txt for the post-reinstall verification.
