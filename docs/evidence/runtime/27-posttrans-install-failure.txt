======== 2. diagnosis ========

The three warnings in the transcript name three separate defects; A37 is the
one that lost the module.

A37 (S2), ordering. `%posttrans` as shipped in 0.6.2-1 ran the build+install
loop first and the stale-registration purge last. `dkms install -m sm750hdmifb
-v 0.6.2 -k <kernel> --force` does not simply place a module: it first
uninstalls the older registered version for that kernel. The 0.6.1
registration was broken - rpm had erased the 0.6.1 package's files, so
/var/lib/dkms/sm750hdmifb/0.6.1/source dangled - and dkms refused:

    Error! Could not locate dkms.conf file.
    File: /var/lib/dkms/sm750hdmifb/0.6.1/source/dkms.conf does not exist.

That exits non-zero, the scriptlet reported `warning: dkms install failed for
7.3.4-100.fc43.x86_64; run it manually` and moved on to the next kernel, with
the same result. Only then did the purge run, met the same broken entry, and
gave up with `Manual intervention is required!`. The purge was correct and
useless: it ran after the step it needed to protect.

The second half of the fix is that a defective registration tree must be
removable. dkms itself instructs it in the transcript:
`If this module version is no longer needed, you can remove the stale
directory.`

A38 (S3), `CLEAN`. `Deprecated feature: CLEAN
(/var/lib/dkms/sm750hdmifb/0.6.2/source/dkms.conf)` is the only effect of the
`CLEAN=` directive. In dkms 3.4.4 the whole script contains one occurrence of
`CLEAN` (/usr/sbin/dkms:582-585) and it is the deprecation emitter; the value
is never executed. Deleting the line removes the warning and changes nothing
else.

A39 (S3), console hint. Unrelated to packaging, found in the same session on
the same host through tools/sm750-console.sh: with a test card on screen the
helper printed

    scanout nonzero: 200323
    scanout crc32: 0x3972ef44
    (crc32 0xe20eea22 is 262144 zero bytes: nothing has painted the window)

The last line is a zero-frame hint and the frame was not zero: 200323 nonzero
bytes and a different CRC. It was printed unconditionally.

======== 3. what changed (0.6.2-2) ========

packaging/sm750hdmifb.spec
  - the stale-registration purge block now precedes the build loop; the
    rationale comment states why the order is load-bearing (spec:146-185,
    purge body spec:186-227, build loop spec:230)
  - a failed `dkms remove` escalates once: a version directory that exists
    with no readable source/dkms.conf is deleted with `rm -rf --` after
    `warning: removing broken DKMS registration tree: <path>`
    (spec:221-226)
  - `$stale_version` is skipped before it can reach a path when it is empty,
    contains "/", is "." or "..", or carries a byte outside [0-9A-Za-z._-]
    (spec:198, spec:207-212)
  - `dkms_root=${SM750_RPM_DKMS_ROOT:-/var/lib/dkms}` next to
    `modules_root`, with the note that rpm never sets either (spec:139-144)
  - the zero-build warning no longer blames headers:
    `warning: no kernel received the module; check the warnings above and run:
    dkms install -m sm750hdmifb -v 0.6.2 -k <kernel>` (spec:257)
  - Release 2%{?dist} (spec:22), new %changelog entry for 0.6.2-2 (spec:331)

dkms.conf
  - `CLEAN="make KDIR=${kernel_source_dir} clean"` deleted; the file now ends
    at MAKE[0] (dkms.conf:9)

tools/sm750-console.sh
  - the zero-frame hint is printed only when the read CRC is exactly
    0xe20eea22 (tools/sm750-console.sh:104-107); otherwise
    `(crc32 0xe20eea22 is 262144 zero bytes; this frame is not it)`
