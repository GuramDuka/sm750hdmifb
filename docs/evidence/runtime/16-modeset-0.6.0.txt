# WHY THERE ARE TWO ALTERNATE-MODE STEPS
# modetest -s commits the mode and exits at once. When its DRM fd is the last one
# open, drm_lastclose runs the driver's own in-kernel fbdev client restore, which
# re-asserts the preferred 1920x1080 mode. So a dump taken immediately after
# modetest -s returns shows the RESTORED state, not the state that was set. Step 2
# records exactly that (same result T10 saw); step 2b keeps the client alive so the
# 1024x768 CRTC state is observable.
