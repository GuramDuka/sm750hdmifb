3. Unprivileged readability evidence

The mechanism the new attributes use is the one the sibling monitoring
attributes already use: DEVICE_ATTR_RO (mode 0444) collected in
sm750_attr_group and registered with devm_device_add_group(&pdev->dev, ...).

  $ ls -l /sys/class/drm/card0/device/vram_total_bytes
  -r--r--r-- 1 root root 4096 Nov 28 00:25 .../vram_total_bytes
  $ cat /sys/class/drm/card0/device/vram_total_bytes
  16777216
  (uid 1005, no sudo, exit 0)

  $ ls -l /sys/class/drm/card0/device/pm_probe
  --w------- 1 root root 4096 Nov 28 00:25 .../pm_probe

So a 0444 attribute in that group is readable by uid 1005 with no privilege,
and the write-only diagnostic is the only member that is not. tests/
check-sysfs-attributes.sh holds every b8_* attribute to that same shape
(DEVICE_ATTR_RO, listed in sm750_attrs[], show function with dev_get_drvdata,
NULL guard and sysfs_emit only), so the first load of a build that carries the
change is the remaining step, and it is a reload: a VT/console action that
this task does not take.

5. What the sample count does not prove

A recovered i2c timeout returns 0 upward and prints nothing (defect A42,
src/sii902x.c sii902x_write_recovering). Zero retry markers is therefore
compatible with any number of silently recovered retries inside the window,
including hundreds: the log cannot separate "the retry path never ran" from
"it ran and hid its work". The 15 driver lines bound what was printed, not
what happened, and the 4 snapshots bound the ring state at 4 instants, not
the traffic between them. This is exactly the gap the counters close:
b8_i2c_write_timeouts moves by one per timed-out attempt and
b8_i2c_recoveries by one per event-driven bus clear, so after the next load a
soak can distinguish a recurrence from an idle build by reading eleven
numbers instead of reasoning about absent log lines.
