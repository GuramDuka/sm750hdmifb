SM750 DRM/KMS driver: production status

Out-of-tree atomic KMS driver for one PCIe card, version 0.6.2

  • Repository sm750hdmifb, module sm750hdmidrm, version 0.6.2 (src/sm750_drm.c:78)
  • Card SE-DP750A-HDMI, Silicon Motion 126f:0750 at PCI 0000:01:00.0, one HDMI output
  • Kernel floor 6.17, encoded in dkms.conf:8
  • Acceptance record: 6 PASS, 0 FAIL, 1 GAP, the gap being pixel-level proof at the panel

The hardware problem

  • SM750G10-AC revision A1, 16 MiB integrated DDR, 64 MiB BAR0, 2 MiB BAR1 (docs/HARDWARE.md:9-15)
  • No HDMI PHY on the SM750: it emits 24-bit parallel RGB/DVO, and the board's SiI9024ACNU converts that to HDMI (docs/HARDWARE.md:11, :18-19)
  • In-tree Linux support for the chip is the staging fbdev driver sm750fb; the src/ddk750* register layer here descends from it (docs/PROVENANCE.md:27)
  • Capability table: 2D engine (128-bit BitBLT/ROP3), DMA, two cursor layers, scaling done in software (docs/HARDWARE.md:47-58)
  • Three board quirks kept non-fatal: DMA1 IRQ not routed, SiI9024A receiver sense absent, PCI cache-line mismatch (docs/HARDWARE.md:21-32)

Framebuffer path: shadow upload and staging

  • Shadow upload copies reported damage into VRAM through sm750_shadow_upload() (src/sm750_drm.c:1705), one aligned span at a time via sm750_shadow_upload_one() (:1655)
  • With backbuffer_staging=1 a full-frame update is rendered into the off-screen buffer; availability is decided at :3725 from the parameter and a VRAM fit test
  • At 1920x1080 RGB565 one buffer is 4147200 bytes (1920 * 1080 * 2); the driver logs full-frame backbuffer staging enabled (4147200 bytes per buffer) (:3762-3764)
  • Async updates run on a dedicated ordered workqueue: sm750_async_shadow_work() (src/sm750_drm.c:2606), created at :4540
  • sm750_present_staged_frame() (:2425) pokes FB_ADDRESS and polls for the flip; on timeout it disables flips and mirrors updates instead (:2447-2457)

vblank and the CRC engine

  • vblank is paced by the driver's own hrtimer, sm750_vblank_timer_fn() (src/sm750_drm.c:468, set up at :4445), not the generic DRM timer (docs/VBLANK.md:1-12)
  • One entry per vblank: sm750_crc_work_fn() (:3311) reads the window and calls drm_crtc_add_crc_entry() (:3329), then re-arms
  • sm750_scanout_crc32() (:3147) is crc32_le over crc_window_bytes, default 262144 bytes (:235), from the visible scanout offset
  • crc/control and crc/data are created and owned by DRM core; the driver supplies only .get_crc_sources (:4009) and .set_crc_source (:4011)
  • The value proves the VRAM buffer handed to the display engine, not the pixels the panel emits (docs/TEST-STRATEGY.md:597-599)

Test strategy

  • make check: 17 recipe commands (Makefile:32-48), prerequisites at Makefile:30-31, preflight at Makefile:17-28
  • Source-level gates carry planted negative controls: the console-blank gate and the restore-path gate each reject four planted defects (docs/DEFECTS.md:481, :59)
  • Root-only gates: make console-check (tests/check-console-scanout.sh) and tools/sm750-restore-cycle.sh, which refuses to run unprivileged
  • Static analysis is a separate target, make static: sparse, smatch, cppcheck, coccinelle, pahole against a recorded baseline (docs/STATIC-ANALYSIS.md:4-9)
